# ✈️ AI-Powered Airline Assistant

A multilingual, Retrieval-Augmented Generation (RAG) chatbot for airline customer support. It answers passenger queries in **English, Hindi, Spanish, and French**, grounding every response in real airline policy and FAQ documents — and when it can't resolve a query, it escalates it by email to the right airline department with full conversation context.

Built with **React + FastAPI + MySQL + ChromaDB + Google Gemini**.

---

## ✨ Features

- **Grounded, context-aware answers** — responses are generated by `gemini-2.5-flash` strictly from retrieved policy/FAQ chunks, dramatically reducing hallucination.
- **Multilingual RAG** — `gemini-embedding-001` places all four languages in a shared semantic space, so a Hindi question can retrieve an English policy paragraph and get answered in Hindi.
- **Hierarchical, structure-aware chunking** — documents are split along their heading structure first (sections → paragraphs) with overlap, and every chunk carries metadata (`doc_title`, `section`, `language`).
- **Vector search with ChromaDB** — persistent local collection, cosine-similarity top-k retrieval with metadata filtering.
- **Secure authentication** — JWT-based sessions, bcrypt-hashed passwords.
- **Query logging** — every question, retrieved context, answer, language, and confidence score is logged to MySQL for analytics.
- **Department routing + human-in-the-loop escalation** — unresolved/low-confidence queries are classified into a department (Baggage, Refunds, Special Assistance, General) and emailed via SMTP to that team with the conversation transcript.
- **Scope guard** — greetings/small talk get a friendly conversational reply steering to airline topics; off-topic questions (recipes, weather…) get a professional "airline queries only" redirect. Neither is escalated — only genuine airline questions the knowledge base can't answer reach a human.

## 🧰 Tech Stack

| Layer            | Technology                                                       |
| ---------------- | ---------------------------------------------------------------- |
| LLM              | Google **Gemini 2.5 Flash** (`gemini-2.5-flash`) via `google-genai` SDK |
| Embeddings       | **`gemini-embedding-001`** (multilingual); local alternative: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` |
| Vector store     | **ChromaDB** (persistent client)                                 |
| Backend          | **Python 3.11+ / FastAPI** + Uvicorn                             |
| Frontend         | **React 18** (Vite)                                              |
| Database         | **SQLAlchemy ORM** — SQLite by default (zero-setup dev), **MySQL 8** via `DATABASE_URL` (`PyMySQL`) |
| Auth             | JWT (`PyJWT`) + `bcrypt`                                         |
| Email escalation | `smtplib` (SMTP, e.g. Gmail app password)                        |

## 🚀 Getting Started

### 1. Prerequisites
- Python 3.10+, Node.js 18+ (MySQL 8 optional — SQLite works out of the box)
- A **Gemini API key** from [Google AI Studio](https://aistudio.google.com/)

### 2. Environment variables (`.env`)

```env
GEMINI_API_KEY=your_google_ai_studio_key


DATABASE_URL=sqlite:///./airline.db

JWT_SECRET=a_long_random_string

# Optional — leave blank to record escalations without sending email
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your_email@gmail.com
SMTP_PASSWORD=your_app_password
```

### 3. Database

Tables (`users`, `query_logs`, `departments`, `escalations`) are **created and seeded automatically** on first backend start. For MySQL, create the database first (`CREATE DATABASE airline_assistant;`) and set `DATABASE_URL` accordingly.

### 4. Backend

```bash
cd backend
pip install -r requirements.txt
python rag/ingest.py          # index docs/ into ChromaDB
uvicorn main:app --reload     # http://localhost:8000
```

### 5. Frontend

```bash
cd frontend
npm install
npm run dev                   # http://localhost:5173
```

## 📚 Knowledge Base (RAG)

The seed reference document is [`docs/airline-rules-and-regulations.pdf`](docs/airline-rules-and-regulations.pdf) — a one-page airline policy sheet (baggage, check-in, cancellations, special assistance, delays, escalation contacts) whose clear section structure is what the **structure-aware chunker** exploits.

To add knowledge:
1. Drop PDFs / Markdown / text files into `docs/`.
2. Re-run `python backend/rag/ingest.py` — it re-chunks, re-embeds, and upserts into the ChromaDB collection.

| ------ | ---------------- | -------------------------------------------------- |
| POST   | `/auth/register` | Create account (bcrypt-hashed password)            |
| POST   | `/auth/login`    | Returns JWT access token                           |

| POST   | `/escalate`      | Manually escalate a conversation to a department   |
| GET    | `/health`        | Liveness check                                     |

## 📨 Escalation Flow

1. After generation, the pipeline scores answer confidence (retrieval similarity + model self-check).
2. If the answer is low-confidence or the user marks it unhelpful, the query is classified into a department: **Baggage Services, Refunds Desk, Special Assistance, or General Support**.
3. An SMTP email is sent to that department containing the user's query, language, conversation transcript, and retrieved context — enabling a human agent to pick up exactly where the AI left off.
4. The escalation is recorded in the `escalations` table with status tracking.
